## 处理差异与保留条件

仅将每题规划中的吞吐惩罚从 0.005 改为 0、功率变化惩罚从 0.001 改为 0，并将实际执行的充电死区从 20 kWh 改为 0。未改变可行域，也未重新训练、校准或筛选预测模型。

继续使用 exp008 的单 HGB + Ridge28 + 非递归 0.5 负荷能量记忆预测；日内负荷修正、附件3官方光伏及其历史校准、Q4 电价预测全部保留。不是 Q2 的 HGB/ExtraTrees 融合预测。每个目标日仅在 00:00、06:00、12:00、18:00 更新；历史路径来自此前 28 个完整目标日在同发布时间的预测残差，按原 `linspace` 规则选择 7 条代表路径。随机种子仍为 42。

当前执行块内规划缺电权重为 5，下一合法更新之后仍为 1.5；继续使用原终端库存经济价值代理，最后评估日为 0。这些代理值不计入实际账单。实际账单按原始购电、一次最终偏差调整及五倍应急费用独立重算。

电池容量 12,000 kWh，SOC 范围 1,200–10,800 kWh，充/放电各自效率 `sqrt(0.9)`，功率上限 5,000 kW。Q3 初始 SOC 为 1,507.622628752613 kWh，Q4-3 为 1,522.7387288211346 kWh；初始实际功率均为 172.75999999999976 kW，方向为充电。随后每个新处理传播自身真实 SOC 与实际动作，不复用 exp008 后续日期的状态。

## 方法及审计边界

`experiments/exp009/run_update_cost_only.py` 直接调用未修改的 `experiments.exp008.run.run_case`，并传入本目录下 `full334` 的绝对路径。运行前显式验证 `Path` 拼接最终落在 exp009，未重定向或改写 exp008 的全局目录变量。

原规划仍是共享购电、场景独立电池回溯的连续七路径 LP，属于乐观规划近似，不是具有非前视执行证明的场景树。实际执行保留原因果贪心规则，且单独检查无同时充放电、无应急充电、功率/SOC/能量平衡及跨日连续性。零辅助目标可能增加动作频率，所有电池指标只作诊断，不用于筛选本次结果。

每题完整记录并比较 1,336 次发布的负荷、光伏、电价数组 SHA256，以及全部 28 条净负荷/价格误差路径 SHA256；同时比较预测审计元数据、历史来源和 7 条代表路径的选取。对照原目录为 `data/results/exp008/absolute_hgb_update_dispatch/full334/{3,4-3}`。原脚本作为 `__main__` 运行，现在通过原模块导入，因而身份字符串的模块限定名不同；原类名、源码 SHA 和全部模型、数据、预测数组身份保持相同，该描述性差异明确单列。

8 组固定未来扰动检查见 `causality_verification.json`。Data 类会载入完整 CSV，因果边界指规划仅使用合法历史前缀及当时已发布数据，并由未来后缀扰动核验；不声称未来行从未载入内存。原 HGB 拟合与校准因果证据沿用原冻结文件，不进行重训。
