# 全 28 条历史路径共同选择购电量与充放模式：五日诊断

这是未达最终目标的开发诊断，不是连续年度结果，也不纳入年度达标排名。五日分别沿用既有 `hold1_cap8` 年度方案当日开始时的 SOC、前一计划方向及持续时间；本试验改变的日末库存没有传播到下一天。

既有方案用 3 条历史路径和 5 秒上限初始化共同模式，然后以全 28 条路径的真实贪心执行目标优化购电量。这里将初始化也改成全部 28 条历史路径、60 秒上限；固定每日最多 8 次计划换向，最短保持 1 个十分钟时段，禁止同时充放与紧急电充电，容量、效率和功率不变。每个候选仍用同样的 120 次上限进行购电优化，再按历史目标在新初值与新优化值间选择。五日选择及文件哈希全部锁定后才读取当日实际负荷和光伏。

改善集中于日序 90；其余四日合计费用增加 42.6181 元。日序 90 同时多消耗 643.1908 kWh 的库存，因此其当日费用下降不能直接视为跨日节约。`terminal_sensitivity.csv` 给出按原内部终端估值 0.45 元/SOC-kWh 及最大时段紧急购电价值调整的敏感性；这些调整都不是题目实际收费或未来实际收益。

5 个 MIP 均取得可行解，但均未达到预设 0.2% 间隙，均在 60 秒上限附近结束。5 次购电优化也均没有收敛成功标志。全路径初始化仍允许每条路径拥有知道整条路径的电池补救动作，是乐观代理；同终端估值下，它与相同 Q 的真实贪心历史执行目标仍相差 1,656.69、141.46、386.81、175.17、78.23 元。因此，扩大历史情景数或延长 MIP 时间没有解决实际反馈策略与初始化补救策略的差别。

独立审计 `independent_audit.json` 不调用求解器：重新读取原始负荷/光伏 CSV，复算全部 20 组历史轨迹与 20 组实际轨迹、实际计费、SOC 方程及边界、功率、禁止同时充放和紧急电充电、模式约束和日内 8 次预算；与原方案的 5 组实际轨迹也逐元素一致。15 个非对称未来净负荷扰动验证已执行前缀保持不变。原结果和原年度来源目录均保持原始哈希。

原试验只归档了六个直接源码文件；该清单不应被描述为完整传递依赖闭包。此次审计验证这六份归档及原年度来源目录的哈希，没有伪称补回试验启动时未归档的依赖。

现有证据不支持直接扩大为 334 日高成本求解。下一步应检查能够随已观察状态改变换向时机的执行策略，并使日前购电目标与它一致；该建议不是已验证节约结论。
