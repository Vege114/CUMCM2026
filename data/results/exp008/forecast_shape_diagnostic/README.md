# 预测误差形状诊断

本诊断仅重读已冻结预测，生成7个固定历史统计基线，并检验一个经根任务预先批准的算术校正；没有重训神经网络、搜索树参数或使用附件三。所有新输入均为各自发布午夜之前的完整实际负载/PV及已知星期。2025年已经用于开发，以下不是独立测试。

`annual.csv`、`monthly.csv`、`hourly.csv` 分别给出整体、月份、小时的负载/PV/净需求误差；`daily.csv` 保留净需求日评分，`month_age.csv` 比较每月前7日与其余日。HGB只评价净需求，不把其adapter两列冒称独立负载/PV预测。

## 简单基线没有胜出

过去7/14/28完整日先折为小时均值，跨日作固定20% winsor均值；另三组只在负载上使用同星期的历史日。第七组将28日PV各日曲线按日能量归一化，以其稳健平均形状乘最近7日稳健能量，负载使用同星期28日。没有按当前真值挑选窗口。

最佳简单净需求RMSE为482.91 kW，仍弱于Joint+Ridge28的384.59 kW。负载混合星期的7日均值RMSE978.41 kW，同星期版本降到302.95 kW，但仍弱于Joint+Ridge28的230.37 kW。PV最近7日均值RMSE412.74 kW、归一化形状417.20 kW，均弱于当前310.68 kW。简单均值/形状不能直接替换当前网络。

## HGB较差的证据与解释边界

HGB二月净需求RMSE586.38 kW、偏置+382.08 kW，Joint+Ridge28为298.12、-39.60 kW。HGB代码二月仅以一月周期基底残差训练，`base_is_cnn`训练值全部为0，二月预测却切到CNN基底、该特征为1；这是可直接核对的输入/目标分布变化。二月贡献HGB相对Joint+Ridge28全年多余平方误差的45.56%。

但不能把全部失败归因于冷启动：排除二月后HGB仍为425.67 kW，Joint+Ridge28为391.55 kW。其月偏置在六月-124.93、七月+150.82、八月+162.55、九月+191.98 kW，90日半衰、每月重拟合的历史映射没有像每日Ridge28一样及时消除这些偏移。全年多余点MSE约46.64%来自日均误差、53.36%来自日内偏差；不是单一整体常数偏置。后一句关于适应速度是与代码/误差一致的机制推断，未做新HGB重训消融，不能作唯一原因证明。

## 一个有依据的固定候选

Joint+Ridge28负载日能量残差lag1相关0.6844，PV对应相关-0.0144；净需求为0.3766。每月前7日占23.1%的日数，却贡献51.0%的日净能量平方误差；6/7/9月贡献58.4%。因此检验固定增益0.5的负载日能量记忆：

`load_today = max(0, underlying_joint_ridge28_load_today + 0.5 * mean(actual_load_yesterday - underlying_joint_ridge28_load_yesterday))`。

昨日残差引用昨日**未加memory层**的已发布Joint+Ridge28基底；首个正式日没有昨日正式基底，保持原预测；PV逐值不变。既不拟合增益，也不按月份开关。

该唯一候选净RMSE384.59→375.59 kW，高价净RMSE368.56→358.23 kW，日净能量RMSE4220.32→3723.90 kWh、MAE3117.37→2679.64 kWh。后续独立模块、接口、审计及配对快速规划回放见 `../load_energy_memory/README.md`。这说明持续负载偏置具有可利用的历史信息，不说明PV天气已可预测，也不直接保证物理模式策略的总费用目标。

复现：`OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv/bin/python -m experiments.exp008.forecast_shape_diagnostic`。
