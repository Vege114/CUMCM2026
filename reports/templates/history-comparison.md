# 历史比较可视化要求

此要求适用于每次与此前实验比较，以及报告第七部分和最终对话交付。没有历史实验时说明缺失，不填零、不制造对比。

## 必须展示的内容

- 全年费用优先：并列此前正式策略与本次正式策略；有历史重算时增加“旧预测＋同一基础调度”“新预测＋同一基础调度”“新预测＋正式调度”，辨认预测和调度的贡献。明确种子、评价天数、费用单位和结算协议。
- 预测误差：至少同时显示 WAPE 与 RMSE，完整数据保留 MAE；区分全时段和实际发电时段。不同变量的原始单位分开，统一单位的相对变化可以共用坐标。避免只展示改善指标。
- 计算代价：训练组数和训练、预测、校准、调度等阶段的实测耗时分别展示。不同机器、计时范围或实验数量仅作描述性比较，不能将训练时间下降解释为端到端耗时下降。此前没有记录的阶段标为缺失。
- 技术路线：以并列流程或可逐步展开的流程图说明两轮的输入、预测、选择规则、调度和执行变化；不同的技术名称不是不可比较的理由。

## 可比性与数据

读取全部此前 registry 记录，按正式策略角色匹配。原登记值和新协议重算值必须明确命名，保留旧记录及其来源。分别验证预测与调度的数据、时期、样本范围、时间对齐、积分、物理及计费口径；不可比时不画改善率、连接线或排名。

每个可比数值保留 previous、current、绝对变化及 relative_change_pct；相对变化为 100×(current−previous)/abs(previous)。零分母或缺失值保留空值。WAPE 原值的单位是 %，其绝对差为百分点，相对变化仍为 %，图中不能混用。

图表应直接读核验后的 CSV/JSON。只在显示时格式化，不从报告截图或四舍五入的正文反推。记录实验编号、正式种子、数据文件及原登记/重算来源。

## 图型与交互

费用用并列点图、哑铃图或分组柱图；相对变化用以零为参照的发散条形图，同时提供原始值与差值。多问题、不同指标使用小多图；可比较的面板保持同一尺度、排序和颜色映射。单位不同的原始值不强行共轴。

图面直接标出核心数值与变化方向，鼠标悬停、触摸或键盘操作可查看原值、差值和口径。不要把基本结论藏在交互中。窄屏堆叠面板，文字和数字不得重叠。

`history-comparison.inline.html` 是相对变化图模板：将 `@@DATA@@` 替换为 JSON 数据，保留实际换行；载荷含 title、scope 和 panels。每个 panel 含 title、axisUnit、rows；每行含 label、previous、current、unit、comparable、comparison。模板仅在 comparable 为 true 且 previous 非零时计算变化，否则显示“不可比/缺失”。不得为了连线或排名把不可比数据改成 true。

## 交付检查

- 报告第七部分至少含费用、误差、阶段耗时的比较图或明确的数据缺失说明；技术变化配图。
- 最终对话必须使用 Visualize 实际展示历史比较，不能只给链接、表格或文字。至少展示费用与误差，重要的计算代价变化配图或沿用已展示的同源图。
- 对话图、离线网页、PNG/SVG 和工作簿使用同一份核验数据；对话图可以精选指标，但要标明样本范围并保留失败项。
- 核对原值、绝对差、相对变化、单位、实验编号、种子、历史重算来源和可比性；保留此前实验及不可比原始成绩。
