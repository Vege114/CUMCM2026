## 1. 测速结论

推荐使用 **PPO、32 个并行模拟环境、单 CPU 线程**。一组定义为一个固定奖励方案和一个 RL 训练种子，包括因果首次训练、23 次滚动继续训练及 334 日连续评价。预测固定 exp004 无季节 seed42。

|---|---:|
| 16 环境：每轮 2,304 步采样 + 4 epoch 更新，中位数 | 0.04690 秒 |
| 32 环境：每轮 4,608 步采样 + 4 epoch 更新，中位数 | 0.06255 秒 |

| 单组 5,667,840 步训练 + 334 日回放，外推 | 约 88 秒 |

| 六组按样本 P95 并乘 1.5 预算系数 | 约 13.2 分钟 |

**建议单组预留 2–3 分钟，六组正式计算预留 15–20 分钟；包括正式入口实现、核验、工作簿、报告和可视化，整体预留 40–60 分钟。** 原始外推未逐项加入所有特征准备、冷启动、检查点写盘及验证开销，因此给出更宽工作预算。报告编写和视觉验收时间为工作估计，不是神经网络吞吐的数学外推。

该速度试验仅进行 27,648 个训练步：两种并行数各一次预热、三次测量，另有五日各三次推理。训练计时样本较短，P95 只表示这三个样本的分位值，不是总体 P95 或置信区间。不能由此判断收敛、年度费用改善或电池寿命。为保持纯测速，本轮没有根据任何试验日实际费用调参，测速模型已丢弃。

## 2. 正式六组配置

| 奖励方案 | RL 训练种子 | 角色 |
|---|---|---|
| 总费用 + 轻微吞吐/反转/功率变化罚 | 42 | 预先指定主组 |
| 同上 | 2026、3407 | 训练随机性核查 |
| 仅总费用奖励，共用相同物理约束/动作空间 | 42、2026、3407 | 去除附加偏好的对照 |

每组首次约 100 万步，之后每 14 日约 20 万步，每组累计约 567 万步。固定两层 64 tanh 网络、PPO clip 0.2、Adam 3e-4、4 个 epoch、batch 512、gamma=1 和 GAE lambda=0.95。32 环境仅依据速度选择；本次未依据全年费用选方案、训练种子或超参数。正式曲线报告训练损失、熵和策略变化诊断，固定预算结束仍未收敛时如实披露，不自动追加训练或选有利年份片段。

RL 种子不同于冻结预测种子，六组均使用同一份 exp004 `no_season/seed42`。主方案身份不在看到年度成绩后变更。纯费用对照仍保留共同的 2 kWh 执行死区，去掉的是三个软罚项。

## 3. 优先目标与电池性能

题目真实总费用始终为 `Σp_t*q_t + 5Σp_t*e_t`，即计划购电费与五倍紧急购电费；附加罚项和库存估值不计入账单。

- **硬约束**：有符号电池动作保证充放电互斥；12000 kWh 容量，SOC 1200–10800 kWh，最大充/放功率5000 kW；沿用历史单向 sqrt(0.9) 效率。执行按实际可用电量与实际 SOC 裁剪，禁止额外紧急购电给电池充电。
- **次要偏好**：吞吐 0.002 元/AC kWh；忽略空闲后的方向反转 0.05 元/次；功率变化 0.0002 元/kW。没有额外硬爬坡上限，以免先行牺牲费用目标。
- **输出指标**：总费用、费用分项、紧急电量、吞吐、EFC、同时充放槽数、方向反转、直接相邻槽反转及完整功率波动。此类指标反映运行强度，不等同于经电芯数据标定的寿命模型。

## 4. 午夜信息边界与训练划分

每天午夜基于完整预测、电价、初始真实 SOC 和后续计划 SOC，顺序生成并锁定全部 144 槽购电与电池意图。当天真实 SOC、实况净负荷或奖励不会进入该日后续规划观察。计划全部生成后，实况只用于物理裁剪和结算。

训练窗口只能包含截止日前已完整揭晓的最近至多90日。首次2月1日只用1月9–31日的23天；1月缺少 exp004 预测，明确使用过去数据生成的周期预测回退。2月后只用已归档预测与已完成实况。随机 SOC 用于训练模拟，正式评价连续承接各策略真实 SOC、方向和上一槽功率，统一2月起始 SOC 为1421.7991105135516 kWh。

训练使用历史完整日路径，保持日内实况时间关联。树的九点分布仅给出购电基准和不确定性特征，仍是逐槽边缘分布，不能称为九条联合日场景。有限动作 PPO 替代的是 exp006 动态规划器；无全局最优保证。训练采用日回合库存估值近似；该估值不得抵扣实际费用，末评价日关闭终端奖励。

## 5. 已完成核验

PPO 与规划环境合计 **11 项测试通过**：GAE 数值、同种子可复现、策略参数更新、完整检查点恢复，以及实况篡改不影响午夜计划、真实数据未来截断、极端实况物理守恒、执行前缀因果、完整日锁定、奖励和真实账单分离。新增 Python 文件 Ruff 检查通过。
